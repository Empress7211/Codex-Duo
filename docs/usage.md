# Codex Duo 0.7.2 使用、同步与恢复详解

一个工作区，多个 Codex 窗口。社区独立开发的 macOS 多窗口工具。

多个 Codex 桌面实例分别使用 ChatGPT 订阅或 CC Switch 中的 API 配置，共享本地工作历史。登录、配置、桌面缓存各自独立。受管同步只改造工具拥有的应用副本；安装的官方应用及其配置、认证和 CC Switch 保持原样。

当前为 `0.7.2 / build 21` 实验版本，可从 [GitHub Release](https://github.com/Empress7211/Codex-Duo/releases/tag/v0.7.2) 下载 Apple Silicon 应用包，或自行构建。应用内含 Python，运行时使用本机安装的官方 Codex。默认使用 ad-hoc 签名，尚未完成 Developer ID 签名与 Apple 公证。当前验证范围见 [验证记录](validation.md)，发布变化见 [RELEASE.md](../RELEASE.md)，数据处理说明见 [PRIVACY.md](../PRIVACY.md)。

## 运行要求

- Apple Silicon Mac，macOS 14 或更新版本。
- 用户自己的官方 Codex 桌面应用及本地工作区。启动时自动检测原生应用的实际集成接口，不以固定 build 号判断兼容。
- API 实例需要用户在 CC Switch 中配置自己的 Codex API 供应商；订阅实例由用户在新窗口登录自己的账号。

应用包仅内置 portable Python、所需标准库和 Duo 管理器，不包含 Codex 引擎。用户无需安装 Homebrew、额外 Python 或准备签名材料；应用包不包含作者账号、API key 或运行数据。

## 同步范围

| 方向 | 当前行为 |
| --- | --- |
| 工具实例 ↔ 工具实例 | 项目、会话归属、排序、置顶、会话列表、执行状态及打开会话的消息增量同步 |
| 官方主窗口 → 工具实例 | 项目、会话、执行状态、已落盘内容和完成结果同步 |
| 工具实例 → 官方主窗口 | 写入同一套会话历史；官方运行窗口的内存侧栏和运行事件刷新仍由官方客户端决定，不能保证即时显示 |

官方生成过程中的文字不会逐字写入历史库，因此工具不能从磁盘获得原窗口的逐字输出。远程 SSH 状态、ChatGPT 云端聊天、定时任务、浏览器状态及窗口当前选中项不在此同步范围内。

## 打开和升级

将完整 `Codex Duo.app` 放入 `/Applications` 后打开。运行数据默认位于 `~/Library/Application Support/Codex Duo/runtime`。全新安装不带实例、账号或历史副本；“打开工具.command”打开上述安装位置。

启动器显示 `Codex Duo`，每个受管窗口的标题、Dock 和应用菜单使用管理器中的实例名称，例如“部门 API 登录”或“研究 API 登录”。图标保持原版。实例应用的系统身份绑定固定实例 ID，不随改名改变；同一实例的登录、配置和历史归属继续保留。

全新工作区先点击“连接共享工作区”，再按需要创建 API 或订阅实例。初始没有额外窗口，也不会复制整套历史或预先生成实例应用。首次启动实例时，从本机安装的原生 Codex 建立本地模板及该实例的独立命名应用。Duo 自动发现启动入口、运行脚本和 framework 版本，校验关键接口后只修改受管副本并做本地 ad-hoc 签名，不使用用户的签名私钥。原版更新后，下次启动已停止的实例时自动重建；运行中的副本不热替换。接口缺失或定位歧义会明确停止，并保留旧副本。

已有工作区升级或切换同步前，先在相关**工具实例**中结束任务并正常关闭窗口；运行中的工具后端会阻止切换。设置页的“启用受管同步”会检查历史兼容性，保留旧历史及恢复记录，再切换工具实例的数据链接。官方窗口无需为此关闭。0.6.0 的默认目录和钥匙串服务已采用 Duo 名称，旧版目录与浏览器加密缓存不自动迁移；保留旧数据的用户应先备份，再核对迁移方案。

工作区仍使用旧共用应用时，先正常关闭所有旧工具实例；下次启动时才能更新本地模板并生成对应实例应用。已采用独立实例应用后，各实例的更新只要求该实例关闭，其他新版实例可以继续工作。运行中的应用包不会被热替换。

1. API 实例选择 CC Switch 中的配置，保存 API 配置后启动。工具只提取 API key，使用 `apikey` 模式，不复制订阅令牌，不切换 CC Switch 当前项。
2. 订阅实例首次启动后，在该实例中亲自登录。工具不复制官方窗口的 OAuth；更换机器或加密密钥后可能需要重新登录。
3. “＋ 新增实例”可以继续添加独立 API 或订阅实例。原生 Codex 已经使用订阅时，通常只需再建所需的 API 实例；若确有需要，也允许建立另一个订阅实例。实际数量取决于本机资源。
4. 共享配置同步要求所有工具实例停止；供应商配置保存要求对应实例停止。配置同步不会覆盖登录和各自的供应商定义。
5. 已关闭的实例可以在卡片中点击“改名”。Dock、应用菜单和标题在下次打开时更新，原应用包被替换，不另建实例或登录。名称支持中文，不能含斜杠、冒号或控制字符，最多 80 个字符且 UTF-8 长度不超过 240 字节。
6. 关闭窗口保留应用包，再次从管理器、Finder 或已固定的 Dock 图标打开时复用同一份。应用包包含专属启动入口，在客户端引擎启动前设置独立数据目录，避免直接打开时被转交给原生窗口。已关闭的实例可以在卡片中点击“删除”，清除该实例的受管应用包、独立登录、配置、窗口缓存和专属 IPC 缓存。原生 Codex 和共享项目、会话不会删除。没有实例应用再使用公共模板时，模板也会释放，下次需要时再生成。改名或升级成功后清理过渡应用副本，不积累旧版本。

API 窗口中可在模型与推理强度选择区域使用闪电按钮选择速度。当前会话中选择的档位优先于实例配置默认值，具体可选项取决于模型和客户端能力。速度是请求的服务档位，实际是否接受、透传或加速，以及费用，由供应商和模型决定；请向供应商确认。若普通配置显式关闭 `features.fast_mode`，工具会提示 Fast 档位不会随请求发送。

CC Switch 中选定供应商的 Codex 配置如果包含 `service_tier`，在实例没有此前保存的速度档位时，保存 API 配置会将其作为初始请求档位；未设置时不额外指定档位。修改 CC Switch 后，需先关闭对应实例，再重新点击“保存 API 配置”才能更新导入配置。普通配置同步、重新导入和切换供应商都会保留实例中已有的速度档位；该档位也可能最初来自 CC Switch，因此切换供应商后仍可能请求 Fast，请确认新供应商的支持和费用。

速度增强在生成受管副本时按接口契约自动识别，不依赖固定的客户端版本号或脚本文件名；原生 Codex 更新后，已关闭的实例下次启动时会重新识别。运行中的实例保持原样，需结束任务并关闭后更新。由于增强依赖客户端内部接口，无法保证适配所有未来变更：如果接口变化导致无法确定正确接入点，管理器会提示速度选择不可用，不安装不完整的补丁；原有 API 窗口能力保持可用。

打开“文稿”中的用户项目时，macOS 可能要求该实例授权。受管桌面使用 `Codex Duo Vault` 保存正常加密所需的存储密钥，没有启用 mock keychain 或明文回退。从本机原生创建的模板被各实例复用，改名仅调整外层身份；更换引擎版本、钥匙串被锁定或原有授权缺失时仍可能出现系统确认。Duo 不替用户批准权限，也不保证所有升级免提示。

## 会话占用和续聊

执行状态与会话占用分别判断。任务完成会停止转圈；只有真实写锁释放后另一实例才可续聊。空的 `.lock` 文件不代表仍被占用。

打开已有会话时，受管窗口先恢复会话并核实写入权。核实期间输入区不可发送；恢复成功后才开放。若写入权仍由别的后端持有，窗口会显示占用和重试，不会先给出可编辑的假状态。执行状态从运行中变为空闲时，受管状态事件也会单独更新；这不等同于写入权已释放。

受管实例发现另一受管后端空闲时，会提出续接请求。持有者只有在**全部会话空闲、没有待答审批、没有未完成 RPC 或排队输入**时，才替换自己的 app-server 子进程以释放缓存写锁；桌面窗口保持打开，接手者用自己的登录续聊。有其他任务执行时继续显示占用，待其结束后再尝试。

官方后端可能在任务完成后继续持锁。工具不会替换官方后端或删除锁，这种情况下真实显示“原生窗口占用”，需要等官方自行释放，或由用户结束工作后关闭持有它的官方实例。工具不会把空闲伪装成可接管。

“实时会话”面板可见时每两秒刷新，分别显示执行状态、写入权和占有者；官方后端缺少实时执行事件时，会把基于历史与写锁的判断标为“可能进行中”。状态不明的未命名会话默认折叠。工具的关闭按钮按专用数据目录定位主进程，正常请求退出，不按应用名称批量停止。

写锁冲突提示跟随受管 Codex 窗口的语言设置显示中文或英文。图标保持当前版本的样式。实例卡片保持固定高度；刷新或自动状态更新不会改变卡片尺寸。

## 存储和隔离

启用同步后，所有工具实例使用官方本地历史库、rollout 和同一写锁目录。工具新产生的工作也保存在这套共享历史中。官方 `config.toml`、认证和 `.codex-global-state.json` 仍只读；项目偏好通过工具的共享侧栏状态合并，再由各受管窗口保存到自己的全局状态。

迁移运行目录或删除实例前，工具会将对应会话的文件路径改为共享目录的实际路径，避免原生窗口引用已经消失的实例目录。会话内容和分页历史保持原样；若受影响会话仍由其他窗口持有写锁，会明确提示占用并保留目录。

保留历史中的供应商标识，不再统一改写 canonical 历史。独立实例配置提供本机历史使用的 `custom` / `openai_http` 定义；实际后端由各自登录决定。另一供应商的加密推理内容可能无法继续，遇到明确的后端不兼容错误需使用原后端或新建聊天，工具不会删除内容绕过。

```
runtime/
  manifest.json                  实例清单和同步状态
  profiles/<id>/codex-home/       独立认证、配置、全局状态
  profiles/<id>/user-data/        独立窗口及浏览器缓存
  profiles/<id>/activity/         运行状态及有界消息增量日志
  profiles/<id>/desktop/<实例名>.app  该实例固定拥有的受管应用
  profiles/<id>/desktop/copy.json  实例应用的名称、版本及复用记录
  shared/sidebar-state.json      工具共享侧栏状态
  shared/skills/                  工具共享 Skills
  desktop/Codex Duo Instance.app  按需建立的本地模板，无实例引用后释放
  runtime-state/                 供受管窗口使用的真实状态快照
source/                          当前可审查源代码
assets/                          当前图标与生成脚本
build.sh                         构建启动器
/Applications/Codex Duo.app/     启动器、集成脚本与 portable Python
打开工具.command                 打开上述安装版启动器
```

短 IPC 目录按 runtime 与实例区分，避免深层目录超出 macOS socket 路径长度；不共享各实例的 IPC、认证或整个 home。模板及实例应用使用 APFS 写时复制创建，尽量共享未改动的资源，不能把 `du` 显示的逻辑大小当成新增物理空间；不同登录仍需要各自的浏览器缓存。删除实例释放其应用和专属缓存，关闭与重开复用原包。管理器不再分发固定引擎，本地无引用的模板属于可释放缓存。

实例使用独立 bundle ID，固定引擎及存储加密服务由受管实例复用。副本关闭自动更新，不注册官方 URL 处理器，保留 Electron 完整性检查。发布者可在构建阶段选择自己的签名身份；运行时不创建证书、不修改证书信任，也不要求用户提供签名材料。

API key 从用户选定的 CC Switch 配置读取，并写入实例独立的 `auth.json`。API key 和 CLI 订阅凭据使用文件存储，不能把浏览器存储加密理解为整个 runtime 都已加密。`Codex Duo Vault` 中的存储密钥用于桌面本地数据加密，不是 API key。

runtime 含私人认证、配置、运行状态和共享历史链接，**不要发送给同事或提交 Git**。分发包只包含软件、运行时和说明，不带实例目录或个人凭据；公开包也不应包含绑定某台机器的 `runtime-location.json`。

可读配置、会话文件和备份不依赖作者账号或 Duo 账号，Duo 也不另建云端账号系统。备份会话应覆盖官方共享历史；runtime 中的历史软链接不是完整会话副本。浏览器加密缓存换机器或换存储密钥后可能无法沿用，需要重新登录。备份与恢复前应停止相关写入者，避免复制仍在变化的状态。

## 构建和恢复

全新克隆请先按 [素材说明](../assets/README.md) 准备本地图标。构建机需要 macOS Swift 编译器、兼容的官方 Codex 应用及一份 portable Python 3.11+。Python 后端无第三方包依赖；分发时内置该解释器和标准库，用户无需额外安装。
如果官方旧会话的 rollout 已压缩为 `.jsonl.zst`，切换前只读预检需要 Python 的 `compression.zstd` 支持或本机 `zstd` 命令；缺少解码能力时会停止升级并保留旧数据。

```sh
# 构建可测试包：默认 ad-hoc 签名，使用默认 Duo 数据目录
./build.sh --python-runtime /path/to/portable/python

# 发布者可选：使用构建机上的签名身份；不会把私钥放进分发包
./build.sh --python-runtime /path/to/portable/python --sign-identity "SIGNING_IDENTITY"
```

构建时校验官方 build `20398`（版本 `26.1007.71326`）的脚本及完整性摘要，再准备固定受管引擎。官方应用升级后，工具会阻止不兼容的实例启动；随包引擎不自动跟随官方更新，需要重新核验并构建。`--sign-identity` 只选择构建签名，不自动完成 Hardened Runtime 或公证，发布状态见 [RELEASE.md](../RELEASE.md)。

旧工作区切换失败时会恢复工具链接、配置、侧栏和清单。确认切换成功、旧历史全部包含在原生工作区且无受管进程占用后，才可清理迁移时留下的旧副本；启用后产生的新工作写入原生共享历史。

已有开发验证范围与结果见 [验证记录](validation.md)。本页的实现说明不代表真实 fresh Mac 安装、网络流量或正式分发条件均已验证。
